What this page is

This is the control page for a local bridge. The bridge is a small program on a computer with a screen. It opens one Chromium window on the ChatGPT website and turns that window into a local API. A client such as Kimi Code can then send a normal chat request to that computer. This page does not store your ChatGPT password. It only sends commands to the program.

Do these now, in order

  1. Do not clone GitHub. The repo is private. On your computer, which must have a screen, download the snapshot, enter the folder, and run make night-check. On Windows, use Git Bash. If make is missing, run bash scripts/night-check.sh.
  2. Sign in yourself when the Chromium window opens. Do not press Enter yet. Wait until the terminal prints Logged in. Then press Enter once. Do not type the password on this page.
  3. Wait for NIGHT-CHECK PASSED. Open http://127.0.0.1:8000/dashboard on that same computer. The public page cannot press these buttons.
  4. Paste the secret the script printed into Internal secret and click Save. Account, chat, and model buttons stay hidden until that save succeeds, because those routes return 401 missing internal secret.
  5. Click I have signed in. The banner should say ChatGPT Logged In. The open account button is Adrian (open). Chat titles appear as switch buttons. Model names appear as pick buttons.
  6. Confirm the secret works before any tunnel. The command is curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:8000/v1/debug/break -H "Authorization: Bearer local"
  7. It must print 401. If it does not, stop. Do not start a tunnel.
  8. Write the Kimi config: python -m gpt_bridge kimi
  9. Leave the night-check server running. make watch attaches to that server if it is already up. It does not start a second copy.

What make night-check does

It installs the Python packages, downloads Chromium for Playwright, and creates a control secret in a local .env file if one is missing. It then opens a headed window, which means a real visible browser window, and waits while you sign in. You press Enter only after you can type in the ChatGPT message box. It sends one proof request that should contain the word pong. It starts the server, checks that health says you are signed in, marks the current chat as broken, and sends one more request. That next request must switch chats by itself and leave the forced-broken flag false. If any step fails, the script stops and names that step.

Why the window exists, and why you type the password

A paid ChatGPT account is used through the website, not through a key from platform.openai.com. The bridge drives that website. The window has to be visible so you can sign in and so the page can render. You type the password into ChatGPT’s own login page. The bridge never asks for it, never stores it, and this page has no password field.

What the secret is for, and when a tunnel is safe

The word local is the client key. It is not a secret from OpenAI. The internal secret is a second lock for control buttons such as force break and account switch. Completions still use the word local, because a client cannot send the extra header. A tunnel is a public web address that forwards to this computer. It is safe to start only after the curl command prints 401. That proves a control route without the secret header is rejected. The computer must stay on. Do not share the tunnel address.

From zero to a working Kimi Code call

Do not clone. Download the snapshot, run make night-check, sign in, wait for the pong proof, paste the printed secret into Internal secret, click Save, then confirm 401. python -m gpt_bridge kimi writes three values into the Kimi settings file on the computer running the server: base http://127.0.0.1:8000/v1, key local, and model gpt-subscription. 1. Connection

Use this section to see whether this page can talk to the bridge, and whether ChatGPT is signed in. Reachable means this page received an answer from the bridge program. It does not by itself mean ChatGPT is signed in. Logged in means the visible window has a usable message box. If this page is on the public web and the Bridge URL is still 127.0.0.1, the buttons cannot work. A public page cannot call your computer’s private address. Paste a tunnel address, or open http://127.0.0.1:8000/dashboard on the same computer that runs the bridge.

Bridge URL is the address this page calls. Save stores it in this browser only. The internal secret field is only for the extra lock. Leave it empty until the secret has been created. Paste the same value that night-check printed once. Do not put that value in a chat, a screenshot, or a public page.

Bridge reachable is yes only after a successful poll. Logged in is the sign-in flag from the bridge. Forced broken is true only while the current chat has been marked and has not yet been replaced. Health time is the clock time on the last health answer. Browser names the driver, usually Playwright Chromium, or down when the poll fails. Healthy means the current chat can take a send. Chat is the address of the open conversation. Poll is how recently this page asked for status. It asks again every five seconds. If reachable stays no, the program is not running, the URL is wrong, or a public page is trying to call 127.0.0.1.

2. Accounts

An account here is a label you choose, such as work, plus a folder on the computer that stores that login’s cookies. The registry file stores the label only. Passwords are never stored. You type a password only in the ChatGPT window. The API never receives it, and this page has no password field.

Add account creates the label and the folder. It does not sign you in. After you add a label, use that account, then sign in in the window that opens. Use account switches the open folder. If a completion is already being sent, the switch is refused with HTTP 409. That means the current send must finish before the window may change accounts. A click cannot cut across a send.

The chat buttons under the account use the same switch path as the API. A failed send also switches chats by itself, up to two tries, so you do not press retry for that case.

3. Browser Actions

Login opens the visible window and waits until the message box is usable. You sign in there. Logout clears the saved cookies for the open account so you can sign in as someone else. Restart browser closes the window and opens it again with the same saved login. It does not type a password.

Force break marks the chat. It does not switch chats by itself. The next send sees the mark, writes the line “active chat unhealthy before send”, switches to another chat, and then answers. After that switch, forced broken goes back to false. Mark means “this chat should not be used.” Rotate means “leave this chat and open another.” Send pong sends one completion whose request text asks for the single word pong. Use it as a proof that the signed-in window answered. New chat opens a fresh conversation in the same account.

6. API Reference

A client needs three values. The base URL is where requests go. On the same computer it is http://127.0.0.1:8000/v1. The key is the word local. It is not a key from platform.openai.com, and it does not bill an OpenAI API account. The model name is gpt-subscription. That name tells the bridge to use the signed-in ChatGPT window. It is not a model id from the public API catalog.

Kimi Code uses the base as the provider address, the word local as the key, and gpt-subscription as the model. Write Kimi config writes those three lines into ~/.kimi-code/config.toml on the computer running the server. It leaves other providers in that file alone. The live base below follows the saved Bridge URL, so a tunnel address can be copied after you paste one. Do not share a tunnel address. Anyone who has it can send requests through the signed-in window, because the key is still the word local.

7. Logs

bridge.log is the running record on the computer, in logs/bridge.log. This panel shows only the last twenty lines. They refresh every five seconds, on the same poll as the status rows. A token-shaped string is redacted before it is shown.

rotations.jsonl is one JSON record per chat switch. A rotation record has a time, a reason, and the chat address that became active. The reason says why the switch happened, such as a failed send or a marked chat. If the tail is empty, either the server has not written a log yet, or this page cannot reach the computer. A 502 or 503 in the last payload should include a reason and an error code. login_required means the window needs a sign-in. chat_failure means the send itself failed.
