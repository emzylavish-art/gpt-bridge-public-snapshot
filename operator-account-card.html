ACCOUNT AND CHAT CARD

You type the password in the window. Every curl uses Authorization: Bearer local. Proof is a later GET, not the click itself.

1 · Logout

CURL
curl -s -X POST http://127.0.0.1:8000/v1/session/logout -H "Authorization: Bearer local"
JSON
200 {"browser":"ready","logged_in":false,"healthy":false,"forced_broken":false,"chat_url":"<login page>"}
PROOF
GET /v1/session → "logged_in": false

Same fields on GET /health, plus "status": "ok". chat_url is the open page, not null.

2 · Login

CURL
curl -s -X POST http://127.0.0.1:8000/v1/session/login -H "Authorization: Bearer local"
JSON
200 status snapshot. "logged_in" is often still false. You have not signed in yet.
PROOF
After you sign in: GET /v1/session → "logged_in": true

GET /health shows the same "logged_in": true and "status": "ok". The POST only opens the page.

3 · Chat switch

CURL
curl -s -X POST http://127.0.0.1:8000/v1/chats/switch -H "Authorization: Bearer local" -H "Content-Type: application/json" -d '{"url":"https://chatgpt.com/c/your-chat-id"}'
JSON
200 {"chat_url":"https://chatgpt.com/c/your-chat-id"}
PROOF
GET /v1/session → "chat_url" equals that URL, and "logged_in": true

New chat is POST /v1/chats/new and returns {"chat_url":"<opened page>"}. Proof is the same match on GET /v1/session. GET /v1/chats uses "current" for the same URL. A non-chatgpt.com link is 400.

Proof curl: curl -s http://127.0.0.1:8000/v1/session -H "Authorization: Bearer local". /health needs no key. One window, one account, one chat.
